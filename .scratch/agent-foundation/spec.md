# Agent 基础版

Status: accepted

Agent 基础版是完整选址试点之前的独立里程碑。[风光项目前期选址 Agent 方案](../../docs/early-stage-siting-agent.md)继续作为选址流程和试点验收的基线。

## 已确认的交付边界

- 提供可在本机启动的单人 Web 聊天页。
- 首个模型采用阿里云百炼华北 2（北京）的 `qwen-plus`，以非思考模式验收，通过兼容 OpenAI Chat Completions 的接口接入。连接地址、型号和密钥由服务端配置。用户可以发送消息并流式看到回复，后续消息可以引用同一聊天会话里已经给出的信息。
- 初始提示词定义助手的角色和当前能力边界。在空间工具提供边界和依据之前，Agent 可以协助梳理待补资料，但不输出候选区。
- 地图、圈画和候选区面板随第一个空间选址场景交付。具体业务规则和提示词随相应工具逐步补齐。
- 用户可以新建聊天会话并切回历史会话。后端将聊天历史保存在本机 SQLite，在页面刷新或应用重启后可以继续对话。创建选址任务需要开发人员明确发起选址。
- 提供一个读取服务端当前时间的工具。模型主动请求调用，Agent 执行工具，模型根据工具结果生成回复。聊天页展示工具调用和结果状态。MCP 随第一个有接入需求的业务场景交付。
- 回复中途断开时，保留已保存的用户消息。聊天页标记回复中断，并允许重试同一条消息。

## 应用结构

React 负责 Web 聊天页，NestJS 负责 Agent、模型连接、工具执行、流式响应和会话存储。现有 Python 模型在实际业务接入时作为工具调用。[技术栈决策](../../docs/adr/0006-use-react-and-nestjs-for-agent.md)

NestJS 内使用 AI SDK Core 处理 Qwen 流式输出和多步工具调用。应用定义工具、限制每次生成的执行步数、持有 SQLite 会话记录，并向 React 发送应用定义的文本、工具和完成事件。

## 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 真实模型和多轮对话 | 本机打开聊天页，使用百炼 `qwen-plus` 流式回复。后续消息可以引用同一会话里已给出的信息。 |
| 时间工具 | 询问当前时间后，模型发起调用，服务端执行并把结果交回模型。聊天页显示工具调用和结果状态，回复引用实际读到的时间。 |
| 历史恢复 | 新建两个会话并分别发送消息。刷新页面和重启应用后，两个会话都能重新打开并各自继续。 |
| 回复中断和重试 | 回复过程中断开连接。恢复后可看到用户消息和中断状态，重试同一条消息时会话中只保留一份用户消息。 |
| 选址能力边界 | 用户要求直接推荐某县的候选区时，Agent 说明现阶段能协助整理的资料和继续选址所需的条件。 |
