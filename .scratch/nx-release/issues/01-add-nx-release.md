# 01 · 接入并验收 Agent 发布流程

Status: resolved
Type: task
Blocked by: 无

## 目标

按[规格](../spec.md)交付可从工作区根目录运行的 Nx Release 流程，覆盖发布预演、质量检查、版本提交和 Git tag。

## 验收标准

- 正式发布同步四份清单，生成根日志和一个指向版本提交的附注 tag。验证首发、后续升版、显式版本和冻结安装。
- 预演覆盖首版及 Conventional Commits 的升版场景，原型和文档提交按规格处理。预演保留文件、Git 索引和引用。
- 正式发布只在干净的 `main` 上执行，失败的门禁在写入前中止。
- README 记录操作和恢复步骤，ADR 记录发布边界。在临时克隆验证真实发布。

## Answer

- Nx 24.0.6 统一管理 Web、API 和共享聊天包的发布，连同根清单同步升版。README 记录了预演、正式发布和 Git 提交或 tag 失败后的恢复步骤。ADR 0008 记录发布边界。
- 在无远端的临时克隆中实际发布了 `v0.1.0` 和 `v0.1.1`。两次均验证了四份清单同步、根日志随版本提交写入、附注 tag 指向该提交以及冻结安装通过。格式、ESLint、4 项 API 集成测试和构建通过。
- 预演验证了 `fix`、`feat`、破坏性变更及显式版本覆盖。纯文档和纯 Python 原型提交均未触发自动升版。Agent 与原型改动同处一个发布区间时，根日志包含符合 Nx 分类的原型条目。
- 验证了开发分支预演，以及正式发布对非 `main`、分离 HEAD、未跟踪文件、未暂存改动、已暂存改动和失败的格式检查的拦截。两路审查发现了继承 `NX_DRY_RUN` 可能跳过门禁的问题，修复后重跑了真实发布、预演及 Git 状态检查。正式仓库的首发由维护者在合入后执行。
